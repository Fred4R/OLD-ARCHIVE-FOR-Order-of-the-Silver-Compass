# Illustrative story proposals

Files in this directory are immersive narrative proposals, not automatically accepted project history.

Each story file must declare:

- `RECORD_TYPE: illustrative_story`
- `CANON_STATUS: PROPOSAL`
- `EVIDENCE_CLASS: A7`
- a continuity basis identifying the project state it draws from.

An illustrative scene may use established setting, characters, relationships, army references, and current scene position. It may add transient sensory detail and proposed dialogue. It must not silently convert those additions into established history.

If Fred later accepts a durable event from an illustrative story, record that accepted development in the appropriate continuity home with its own evidence and scope. Do not treat the mere existence of the story file as acceptance.


## Symbolic use of repository work

Read `../../CONTINUATION.md` before using repository actions as story symbolism. Use the action's function, not its literal technology: verification may become a seal check; authority routing may become a steward's ledger; an unresolved field may become an intentionally open docket. Never make GitHub, validators, files, or AI tooling literal in-world facts.

A symbolic echo remains illustrative unless separately accepted. It should deepen the current scene rather than interrupt it, and it must preserve Fred's agency and every character's actual knowledge.
