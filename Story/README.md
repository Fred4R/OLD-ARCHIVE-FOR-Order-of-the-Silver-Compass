# Story continuity records

This directory contains narrow, durable records that support immersive story continuation without turning assistant narration into accepted history.

These records are derived routing and continuity aids. They do not replace the evidence that supports a claim, upgrade inherited evidence, create private motives, or convert proposals into canon.

## Records

- `CURRENT_SCENE.yaml` — structured current staging, participant-count safeguards, immediate lived beat, and spatial uncertainty.
- `EVENTS.yaml` — durable event and waymark index for accepted or inherited project history already supported elsewhere.
- `KNOWLEDGE.yaml` — explicit who-knows-what claims where the repository already supports that knowledge relation.
- `ACCEPTANCE.md` — rules for deciding what a live conversation actually establishes before any durable writeback.

Fred's own user-authored continuity and agency boundary are stored separately in `../Characters/Fred.md`.

## Continuation route

For an ordinary story continuation:

1. read `../CURRENT_STATE.md` first;
2. read `CURRENT_SCENE.yaml` when presence, staging, location, or immediate sensory state matters;
3. read `KNOWLEDGE.yaml` when a character's knowledge or ignorance matters;
4. read `EVENTS.yaml` when earlier events, chronology, or waymarks matter;
5. retrieve the relevant character and relationship records;
6. use the preserved MASTER only for underlying evidence, unextracted history, or reconciliation.

Do not preload every story record merely because a scene continues.

## Portrayal boundary

`../Characters/Constantia-Serenitas.md` is currently the only dedicated lore-grounded A6 simulation guide. Other principal people have continuity records but no equivalent simulation guide yet.

For another person's portrayal, preserve the established continuity first. When official Warhammer role or institutional context materially affects the scene, research the current controlling Games Workshop/Warhammer source and keep any behavioral synthesis explicitly interpretive unless later evidence establishes it.

The methodology PDFs under `../Sources/Methodology/` may discipline A6 interpretation when a genuine identification question arises. They are not a covert personality test and do not create fictional biography or private mental state.

## Update order

When a live conversation establishes a durable story change:

1. apply `ACCEPTANCE.md` to determine the smallest fact actually established;
2. update the authoritative durable home for that fact;
3. update `CURRENT_SCENE.yaml`, `EVENTS.yaml`, or `KNOWLEDGE.yaml` only when its scope actually changes;
4. update `../CURRENT_STATE.md` last when the operational pointer or continuation-critical summary changed;
5. preserve unresolved boundaries instead of inventing completion.

A repository write is workflow evidence, not proof that the fictional claim deserved acceptance.
